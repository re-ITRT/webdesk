# 决策记录：管理界面以 Web 应用形态交付（“吃自己的狗粮”）

**日期**：2026-08-25
**决策**：弃用 WPF 原生管理界面，将管理界面做成一个 Web 应用，并让它成为平台内置的第一个默认 Web 应用。
**状态**：已采纳（已落入需求规格 V1.3，见 `docs/requirements/requirements-v1.2-draft.md` 第 2.7 节）

---

## 一句话

我们不“写一套管理软件”，我们写一个**管理 Web**（后台服务在 localhost 托管管理 API + 静态页面），然后让这个管理 Web 注册为平台上的**第一个默认 Web 应用**。

## 为什么成立

1. **平台的一切能力都被自身日常调用（dogfooding）**：控制台跑在模式 B，被注入 / 钩子 / 后台驻留 / 托盘唤出管理——每个功能点天天被自测，回归问题第一时间暴露。
2. **界面与渲染技术栈合一**：管理界面 = HTML/CSS/JS，与它管理的 Web 应用同一套技术；不再维护“原生 + Web”两套 UI 栈。
3. **“恢复通道”反而更强**：控制台是 localhost 页面，内置渲染（模式 B）异常时，仍可用普通浏览器打开 `http://127.0.0.1:<port>` 访问——本地 HTTP 同时充当故障恢复路径。
4. **跨平台顺带受益**：未来 macOS 只需移植原生内核壳，界面零改动。
5. **可编程 / 可测试**：管理 API 是普通 HTTP，curl / 脚本即可驱动，自动化测试与未来的 LAN 远程管理（opt-in）成为可能。

## 业界先例

这个模式非常成熟：**Home Assistant、Pi-hole、Unraid、路由器管理后台、ComfyUI / Ollama（Open WebUI）**——都是“本地 daemon + Web 控制台”，桌面壳只是入口。区别在于：我们更进一步，**把控制台本身注册成平台的第一个应用**，用平台自己的能力承载自己。

## 架构变化

```
┌──────────────────────────────────────────────────────────────┐
│                    WebDesk 系统                               │
│                                                               │
│  ┌────────────────────────────────────────────────────┐      │
│  │  原生内核（daemon，常驻进程）—— 全部“看不见的部分”   │      │
│  │  · 托盘 / 系统通知 / 开机自启                       │      │
│  │  · 单例互斥体 + 命名管道 IPC（启动器转发）           │      │
│  │  · 应用调度器 / 生命周期钩子执行器 / Job Object      │      │
│  │  · Chrome 探测 & 模式 A 启动 / WebView2 承载         │      │
│  │  · 本地 HTTP 服务器（管理 API + 静态控制台资源）     │      │
│  └───────────────┬────────────────────────────────────┘      │
│                  │ 127.0.0.1:<random-port>（仅回环 + token）  │
│  ┌───────────────▼────────────────────────────────────┐      │
│  │  管理控制台 = 内置 Web 应用（模式 B，首个默认应用）   │      │
│  │  · 应用增删改查 / 钩子 / 注入 / 扩展配置             │      │
│  │  · 浏览器直开 localhost 可作恢复通道                │      │
│  └────────────────────────────────────────────────────┘      │
│                                                               │
│  其它 Web 应用（模式 A / B 并存，全部由平台管理）…            │
└──────────────────────────────────────────────────────────────┘
```

- **原生内核收窄为“看不见的部分”**：托盘、通知、快捷方式、单例/IPC、钩子执行、Chrome 探测与模式 A 启动、Job Object 进程回收、本地 HTTP 服务器。
- **所有“看得见的部分”都变成 Web**：管理控制台 + 用户管理的所有 Web 应用。
- 托盘“显示主面板” = 激活控制台应用窗口。

## 新增需求（已落入需求规格 V1.3）

- **2.7 内置默认应用：管理控制台**——预置 `WebDesk 控制台`（`renderEngine: "embedded"`，URL 指向本机端口）；可删除、可经管理 API 恢复重建。
- **3.4 管理 API 暴露面**——仅绑定 `127.0.0.1`、随机端口、会话级 token。
- **第 4 / 5 章**——架构与 UI 原型按 Web 形态更新。

## 安全边界

- 仅绑定回环地址；随机端口；管理 API 破坏性操作需会话 token。
- 普通互联网页面因 CORS / Private Network Access 限制无法触达 localhost，但**本机任意进程**可触达——因此管理 API 的破坏性操作一律需要 token，且不以明文写死在页面静态资源里。
- 控制台应用标 `isSystem: true`，避免在应用网格里被误当作普通应用（可隐藏或加“系统”徽标）。

## 对原型的影响（利好）

首个里程碑大幅缩水：**不需要任何原生 UI 代码**。

- 可运行的最小闭环 = C# daemon（本地 HTTP + 调度 + 单例）+ 静态控制台页（增删改查应用）+ 一个模式 B 承载窗口。
- 之后每加一个平台能力（钩子、注入、驻留…），都在控制台上“长出”对应管理入口，边做边吃自己的狗粮。

## 保留的候选（当前未选）

- 若未来需要强原生体验（如开机引导向导、系统级安装器 UI），可单独为那部分保留极小原生壳，管理主体仍走 Web。
